# Jev opponents

To watch a game without playing, create a Power Grid lobby and change **Your role** to **Watch a bot play my seat** or **Watch Jev play my seat**. Fill the other seats using **Add bot** and **Add Jev**, then start. Your host controls and saved-game access remain available, but the board and game actions are read-only. The role can be changed back before starting and is locked after start. **My games** leaves the game running; **Quit** retains its existing meaning of giving up the seat (and removing a table when no human participants remain).

Copy `.env.example` to the repository-root `.env`, set `JEV_API_KEY` to your TypeSafe key, and restart the server. `TYPESAFE_API_KEY` is also accepted. Never use a `VITE_` variable for this key. The server entry point loads the root `.env`; existing process environment values take precedence. Requires Node 22+ for the built-in environment-file loader and SQLite.

The host can choose **Add bot** for the existing local strategist or **Add Jev** for a TypeSafe opponent. Adding Jev without a key returns a configuration error. Each Jev seat keeps its identity across restarts.

The implementation follows the [official HTTP quickstart](https://docs.typesafe.ai/introduction/quickstart) and [Choice contract](https://docs.typesafe.ai/primitives/choice): server-side POST to `https://api.typesafe.ai/v1/systemone`, model `jev-latest`, shared state and a typed Choice question. Legal action candidates cover setup, bounded sealed bids, scrapping, complete resource baskets, building and production. The local strategist is never consulted to generate or rank Jev's choices. Bids remain sampled; large resource-basket spaces are sampled across the entire legal enumeration rather than truncating its prefix. This is a candidate selector rather than an exhaustive action interface.

Every phase includes public settings, player inventories and network status, plant-market status, supply reserves, auction eligibility, step/endgame status, and the map. Jev also receives current-board expansion costs (including unaffordable targets), all stored-fuel production combinations, the full income table, refill tables, and the effective city thresholds. These are mechanical facts, not move scores or strategy advice. The mechanics briefing in `jevRules.ts` covers the implemented sealed auction, deferred settlement of combined build-and-power turns, map rules and variants. No budget targets or forced expansion rules are imposed. Each request is independent; no model conversation history is retained.

Context excludes player names, accounts, credentials, chat, logs, random seed, hidden deck order and rival sealed commitments. Every result must name an offered action and pass authoritative validation. Requests have a five-second default timeout and no automatic retries. Errors use the local strategist; stale responses are discarded. One-choice turns need no paid request. No live paid request is made by the automated test suite; actual provider access and play quality require a configured account.
